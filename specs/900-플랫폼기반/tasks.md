# Tasks: 900 플랫폼 기반 FR-001~021

> 근거: `specs/900-플랫폼기반/spec.md`, `specs/900-플랫폼기반/design.md`  
> 원칙: 한 작업은 하나의 검증 가능한 목적만 가진다.

## 구현 순서

### T-900-001 플랫폼 모듈과 초기 마이그레이션

- 기존 Spring Boot 애플리케이션에 platform 패키지 경계를 만든다.
- 계정·세션·로그인 이력 테이블을 만든다.
- 역할·권한·조직 범위·권한 변경 로그 테이블을 만든다.
- 회사·사업장·부서·부서 버전 테이블을 만든다.
- 공통 코드와 연도별 설정 버전 테이블을 만든다.
- Hibernate `ddl-auto=validate`를 유지한다.

관련: FR-001~021, AC-001~021.  
완료: 빈 MySQL에 Flyway 적용·재실행과 JPA validate가 통과한다.

### T-900-002 계정과 비밀번호

- 계정을 사원 ID와 1:1로 연결한다.
- Spring Security bcrypt 해시만 저장한다.
- 비밀번호 정책을 환경 설정으로 주입하고 변경 시 검사한다. 기본값은 최소 12자, 최근 5개 재사용 금지이며 추가 문자 조합은 강제하지 않는다.
- 재사용 금지 이력을 보존한다.
- 활성·잠금·비활성 상태를 구현한다.

관련: FR-001, FR-003, FR-004, FR-008; AC-001, AC-003, AC-004, AC-008.  
완료: 평문 비저장, 정책 위반 거부, 상태별 로그인 거부 테스트가 통과한다.

### T-900-003 로그인과 이력

- 로그인 API를 구현한다.
- 계정 없음과 비밀번호 오류를 동일 응답으로 처리한다.
- 더미 해시 검증으로 계정 존재 여부 노출을 줄인다.
- 성공·실패 로그인 이력을 저장한다.
- 연속 실패 횟수와 잠금 만료를 원자적으로 처리한다. 기본값은 연속 5회 실패 시 15분 잠금이다.

관련: FR-001~004, FR-010; AC-001~004, AC-010.  
완료: 성공·동일 실패 응답·동시 실패 잠금·이력 테스트가 통과한다.

### T-900-004 서버 저장형 세션

- 불투명 세션 토큰을 생성하고 DB에는 다이제스트만 저장한다.
- Secure·HttpOnly·SameSite 쿠키와 CSRF 보호를 적용한다.
- 만료, 현재 로그아웃, 전체 로그아웃을 구현한다. 기본값은 최대 8시간, 유휴 30분이다.
- 계정 비활성 시 모든 세션을 무효화한다.

관련: FR-005, FR-006, FR-008; AC-005, AC-006, AC-008.  
완료: 원문 토큰 비저장, 만료·로그아웃·퇴사 차단 테스트가 통과한다.

### T-900-005 역할과 기능 권한

- 역할·권한·계정 역할 API와 영속성을 구현한다.
- 일반 권한과 민감 작업 권한을 독립 코드로 관리한다.
- 변경 로그와 변경을 한 트랜잭션으로 저장한다.
- 세션 다음 요청부터 변경된 권한을 적용한다.

관련: FR-011, FR-014, FR-015; AC-011, AC-014, AC-015, EC-008, EC-009.  
완료: 역할 조합, 민감 권한 분리, 변경 즉시 반영, 로그 실패 롤백 테스트가 통과한다.

### T-900-006 조직 범위와 본인 접근

- SELF·DEPARTMENT·DEPARTMENT_TREE·WORKPLACE·COMPANY 범위를 구현한다.
- 기능 권한과 대상 사원의 조직 범위를 함께 판정한다.
- 본인 데이터 접근을 별도로 허용한다.
- API 및 application 계층에서 fail-closed로 강제한다.
- 010의 AuthorizationChecker를 실제 어댑터로 연결한다.

관련: FR-012, FR-013, FR-016; AC-012, AC-013, AC-016.  
완료: 역할·범위·본인 여부 조합과 010 직접 API 우회 테스트가 통과한다.

### T-900-007 회사와 사업장

- 단일 회사와 사업장 등록·조회·수정 API를 구현한다.
- 사업자등록번호·소재지·업종·개시일을 관리한다.
- 활성 기간과 유일성 제약을 적용한다.

관련: FR-017, AC-017.  
완료: 정상·중복·유효기간 경계 테스트가 통과한다.

### T-900-008 부서 시점 이력과 트리

- 부서 안정 ID와 유효기간 버전을 구현한다.
- 신설·이동·명칭 변경·폐지를 새 버전으로 기록한다.
- 기준일 트리를 조회한다.
- 기간 겹침·순환·사업장 불일치를 거부한다.
- 010의 OrganizationReader와 OrganizationSnapshotReader를 실제 어댑터로 연결한다.

관련: FR-018, AC-018.  
완료: 여러 기준일 트리와 동시 변경·잘못된 계층 테스트가 통과한다.

### T-900-009 공통 코드

- 코드 그룹과 코드 등록·조회·비활성 API를 구현한다.
- 직위·직책·직무 코드를 제공한다.
- 사용 중인 코드의 삭제를 거부한다.

관련: FR-019, AC-019.  
완료: 그룹·코드 유일성, 참조 중 삭제 거부, 비활성 조회 테스트가 통과한다.

### T-900-010 연도별 설정 이력

- 설정 종류·연도·범위·버전·값·근거·확인자를 저장한다.
- 변경 시 기존 행을 수정하지 않고 새 버전을 추가한다.
- 대상 연도 값이 없을 때 명시적으로 실패한다.

관련: FR-020, FR-021; AC-020, AC-021, EC-012.  
완료: 연도별 조회, 버전 이력, 누락 연도 오류 테스트가 통과한다.

### T-900-011 React 관리 화면

- 로그인·로그아웃 화면을 구현한다.
- 계정 역할과 조직 범위 관리 화면을 구현한다.
- 사업장·부서 트리·공통 코드·연도별 설정 화면을 구현한다.
- 메뉴 숨김과 별개로 서버 거부 결과를 처리한다.

관련: FR-001, FR-006, FR-011~021.  
완료: 키보드 조작, 오류 연결, 권한별 사용자 흐름 테스트가 통과한다.

### T-900-012 010 통합과 최종 검증

- 기존 010의 fail-closed 포트를 900 실제 어댑터로 교체한다.
- 사원 등록, 기록카드, 발령, 퇴사, 조직 현황 회귀를 실행한다.
- FR-001~021과 AC-001~021 검증표를 작성한다.
- 비밀번호·세션·개인정보·비밀키·절대경로 노출을 검사한다.
- 백엔드 테스트·빌드와 프론트엔드 테스트·린트·빌드를 실행한다.

관련: FR-001~021, AC-001~021.  
완료: 검증표와 실행 결과를 PR에 기록하고 Cursor 최종 검증을 요청한다.

## 확정된 운영값

- 비밀번호: 최소 12자, 최근 5개 재사용 금지. 문자 종류 조합은 강제하지 않는다.

- 세션: 최대 8시간, 유휴 30분
- 로그인·권한 변경 이력: 3년 보존. 만료 자동 파기는 후속

T-900-001~004는 이 기본값으로 완료 판정한다.
