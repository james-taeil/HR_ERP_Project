# Product Spec: 인사 · 노무 · 세무 통합 관리 시스템

> v2.0 · 기존 v1.0(122건)과 캔버스 초안(219건)을 병합해 7개 분류로 재구성한 제품 수준 스펙
> 이 문서는 개별 도메인 스펙의 상위 기준이다. 도메인 스펙은 `specs/0N0-<도메인>/spec.md`에 둔다.

---

## 1. 배경

- **이 제품이 필요한 이유**: 인사 업무는 사원 데이터 하나가 근태, 급여, 4대보험, 세무, 교육으로 동시에 흘러간다. 그런데 현장에서는 각 단계가 서로 다른 엑셀 파일과 서로 다른 담당자에게 흩어져 있다.
- **현재 문제**: 입사 한 건이 발생하면 인사 등록, 근로계약서 작성, 4대보험 취득 신고, 법정교육 대상 지정을 각각 다른 도구에서 손으로 반복한다. 같은 값을 여러 번 입력하므로 어디선가 반드시 어긋나고, 법정 기한은 사람이 기억해야 한다.
- **기대 효과**: 사원 데이터를 한 번 입력하면 계약서와 신고 자료, 급여, 교육 대상 판정까지 자동으로 이어지고, 법정 기한은 시스템이 먼저 알린다.

## 2. 목표

- **G-1**: 사원 마스터를 단일 원천으로 삼아 근태·급여·보험·세무·교육이 같은 데이터를 참조한다.
- **G-2**: 법정 신고와 교육 기한을 시스템이 산출해 누락 0건을 만든다.
- **G-3**: 급여와 보험료, 세액 계산은 계산 근거를 함께 저장해 언제든 재현하고 재계산할 수 있다.
- **G-4**: 주민등록번호와 계좌번호 같은 민감정보를 암호화·마스킹·열람추적 세 겹으로 보호한다.
- **G-5**: AI는 판단이 필요한 노무 영역에서 초안과 진단을 제공하되, 저장과 신고는 반드시 사람이 확정한다.
- **G-6**: 트랜잭션, 동시성, 권한, 검색, 배치, 모니터링을 실제 도메인 위에서 익힌다. (학습 목표)

## 3. 비목표

이번 제품 범위에 포함하지 않는다.

- **NG-1**: 기관 시스템(4대보험 EDI, 홈택스)으로의 실제 전송 연동. 서식과 제출 파일 생성까지만 한다.
- **NG-2**: 복식부기 회계 전표와 재무제표.
- **NG-3**: 세금계산서 발행.
- **NG-4**: 채용 관리, 성과평가, 복리후생 포인트.
- **NG-5**: 온프레미스 설치형 배포.
- **NG-6**: 완전한 다국어 번역. 한국어만 지원하고 문자열 분리 구조만 갖춘다.

## 4. 사용자

| 사용자 | 니즈 | 권한과 제약 |
|---|---|---|
| 시스템 관리자 | 회사 설정과 계정, 요율 테이블을 관리한다 | 전체 설정. 민감정보 원문 조회는 별도 승인 |
| 인사 책임자 | 전사 인사·근태·급여 현황을 보고 신고를 확정한다 | 전사 조회, 신고와 급여 확정 권한 |
| 인사 담당자 | 자료를 입력하고 신고를 준비한다 | 전사 입력과 상신. 최종 확정 제외 |
| 팀장 | 팀원 근태와 휴가를 승인한다 | 소속 조직 범위만 조회와 승인 |
| 사원 | 본인 근태와 휴가, 증명서를 처리한다 | 본인 데이터만 |
| AI 어시스턴트 | 초안 생성과 진단을 제공한다 | 호출자 권한 범위 상속. 쓰기 불가 |

## 6. 제품 수준 원칙

개별 도메인 스펙은 아래 원칙을 위반하지 않는다.

- **P-1 단일 원천**: 사원 정보는 인사관리에만 존재한다. 다른 도메인은 복제하지 않고 참조한다.
- **P-2 요율 외부화**: 보험 요율, 세액표, 최저임금, 법정 기한을 코드에 상수로 두지 않는다. 연도별 코드 테이블에 두고 계산 로직은 그 테이블만 참조한다.
- **P-3 계산 근거 보존**: 급여·보험료·세액 계산 결과는 사용한 요율과 입력값 스냅샷을 함께 저장한다. 과거 기간을 재계산하면 당시 규칙이 적용된다.
- **P-4 파생값 금지**: 연차 잔여일처럼 계산으로 얻는 값은 컬럼을 직접 수정하지 않는다. 부여와 사용 이력의 차이로 산출한다.
- **P-5 서버 권한 강제**: 화면 숨김에 의존하지 않는다. 조회 범위와 쓰기 권한을 서버에서 다시 검증한다.
- **P-6 민감정보 3중 보호**: 암호화 저장, 목록 마스킹, 열람 이력 기록을 모두 적용한다.
- **P-7 AI 경계**: AI에는 개인 식별 정보를 전달하지 않는다. 집계값과 익명 식별자만 넘기고, 결과는 초안으로만 취급한다.
- **P-8 확정 불변**: 급여 마감, 신고 확정, 결재 승인 이력은 사후 수정하지 않는다. 정정이 필요하면 정정 기록을 새로 남긴다.

## 7. 성공 기준

- **S-1**: 입사 한 건 처리에 필요한 사람 입력이 1회로 끝난다.
- **S-2**: 법정 기한 알림 누락 0건.
- **S-3**: 신고 자료 합계가 급여·지급 원천 데이터와 항상 일치한다.
- **S-4**: 임의 과거 시점의 급여와 보험료를 당시 요율로 재계산해 원본과 일치시킬 수 있다.
- **S-5**: 권한 없는 사용자의 민감정보 원문 조회 시도가 전부 차단되고 로그에 남는다.

## 8. 의존성

- **기존 시스템**: 없음. 신규 구축이다.
- **외부 서비스**: 오브젝트 스토리지(파일), 메일 발송, AI 모델 API.
- **정책 확인 필요**: 법정 기한과 요율은 시행 시점 고시로 확인해 코드 테이블에 입력하는 운영 절차가 필요하다. 이 문서의 수치는 설계 기준일 뿐 법적 근거가 아니다.

## 9. 결정과 열린 질문

### 9.1 확정된 결정

| ID | 결정 | 근거와 영향 |
|---|---|---|
| **Q-1** | **개발 기간 제약 없음. 스펙은 전 범위를 쓴다** | 단계별 기능 절단선을 두지 않는다. 구현 순서는 스펙 완성 후 별도로 고른다. 따라서 도메인 스펙에 P1·P2 우선순위 표시를 넣지 않는다 |
| **Q-2** | **단일 기업 인사팀 모델** | 대행 사무소 계층을 두지 않는다. 조직은 회사 1개 아래 사업장과 부서로 구성한다. 테넌트 분리 설계가 필요 없고 권한은 조직 범위 기준으로만 판정한다 |
| **Q-9** | **겸직 없음. 사원은 사업장 1개와 부서 1개에만 소속** | 소속이 단수이므로 결재선과 조회 범위를 소속 하나로 판정한다. 사원과 부서는 다대일이고, 겸직 테이블을 두지 않는다. 여러 부서 업무를 겸하는 경우는 발령으로 소속을 옮기거나 프로젝트 단위 임시 배정으로 다루되, 임시 배정은 이번 범위에 없다 |
| **Q-5** | **급여관리는 060 세무관리에 포함. 별도 도메인을 두지 않는다** | 급여 계산과 원천징수, 연말정산이 한 도메인 안에서 이어진다. 각 도메인 스펙의 의존성 항목에 적힌 "급여"는 060 세무관리를 가리킨다. 060의 요구사항 중 급여 계산 부분은 아직 작성되지 않았다 |

### 9.2 Q-2 확정에 따른 조직 구조

```
회사 (1개, 시스템 전체가 한 회사)
 └─ 사업장 (N개, 4대보험 신고 단위 · 사업장관리번호 보유)
     └─ 부서 (트리 구조, 시점 이력 관리)
         └─ 사원
```

- 사업장을 별도 계층으로 두는 이유는 4대보험 취득·상실 신고와 보험료 부과가 사업장 단위로 이루어지고, 사업장마다 업종과 산재 요율이 다르기 때문이다.
- 부서는 사원의 소속과 결재선, 조회 권한 범위의 기준이다.
- 사원은 사업장 하나와 부서 하나에만 소속된다(Q-9 확정). 소속 변경은 발령으로만 이루어진다.

### 9.3 남은 열린 질문

| ID | 질문 | v1.0 | 캔버스 초안 | 영향 |
|---|---|---|---|---|
| Q-3 | 데이터베이스 | MySQL 8 + Redis | PostgreSQL | 인덱스와 캐시 전략, AI 벡터 검색 방식 |
| Q-4 | 모바일 앱 | React Native 포함 | 웹만 | 알림 설계와 배포 파이프라인 |
| Q-6 | 경비 청구 | 8건 포함 | 없음 | 7개 분류 밖 기능의 존치 여부 |
| Q-7 | 기관 신고 방식 | 해당 없음 | 서식 출력까지 | 보험·세무 도메인의 종착점 |
| Q-8 | AI 모델 제공자 | 미정 | 미정 | 민감정보 전송 범위와 비용 상한 |

Q-3부터 Q-8까지는 Specify 작성을 막지 않는다. 다만 각 질문은 아래 단계 게이트에 따라 필요한 시점까지 닫아야 한다.

### 9.4 단계별 진입 게이트

| 단계 | 진입 조건 |
|---|---|
| Specify | 열린 질문을 명시하고 임의로 결정하지 않는다 |
| Plan | Q-3, Q-4, Q-7, Q-8처럼 아키텍처·외부 연동·보안에 영향을 주는 질문을 확정한다 |
| Tasks | 대상 기능의 FR·AC·EC와 도메인 간 입력·출력 계약이 모두 정의되어야 한다 |
| Implement | 대상 작업에 영향을 주는 열린 질문이 없고, 관련 계산 순서·상태 전이·권한·동시성 기준이 확정되어야 한다 |
| Release | 적용 법령·요율·서식의 기준일과 버전, 보안 및 복구 검증 결과를 확인한다 |

범위 밖 질문은 다른 기능의 구현을 막지 않는다. 단, 해당 질문에 영향을 받는 기능은 질문이 닫힐 때까지 구현하지 않는다.

## 10. 검증 계획

- 도메인 스펙마다 요구사항 ID와 수용 기준이 1대1로 연결되는지 확인한다.
- 제품 원칙 P-1부터 P-8까지를 위반하는 요구사항이 도메인 스펙에 없는지 교차 점검한다.
- 구현 대상에 영향을 주는 열린 질문과 도메인 간 계약이 단계별 진입 게이트를 충족하는지 확인한다.
